# 触控板层叠面板工具：竞品调研、可行性与需求细化

Oct 28, 2026 · @Aurnxt

## 结论摘要

**技术上可行，可用性取决于两件事：误唤起控制，以及激活态下对系统手势的屏蔽。** 读取原始触点、冻结光标、显示不抢焦点的浮层、执行快捷动作，这四项都有成熟的开源先例，没有原理性障碍。

- **可行性依据**：Apple 私有框架 MultitouchSupport 能给出每根手指的归一化坐标、ID、接触面积与状态；已有开源工具在 macOS 15 和 macOS 26 上用它做手势，且不影响系统手势。
- **最大技术风险**：原始触点是"只读旁听"，无法吞掉。锚指加指点指在系统眼里就是双指，会产生滚动、缩放、辅助点按。必须在事件层把这些事件丢弃，并把激活态严格限制在两指以内。
- **最大体验风险**：左下角恰好是很多人拇指休息、物理按压的位置。唤起判定必须叠加驻留时长、静止、未按压、无其他手指等条件。
- **分发限制**：用了私有框架和可修改事件的 Event Tap，不能上 Mac App Store，只能走 Developer ID 签名加公证的直装分发。
- **建议路线**：先做 2 周技术原型，只验证"唤起判定 + 事件屏蔽 + 抬起去抖"三件事（见文末清单），通过后再做面板编辑器和动作库。

与 BetterAndBetter 的核心差异：它让用户**记住**上百种手势，我们让用户**看着选**。这在交互研究里有成熟先例（Marking Menu：新手看菜单，老手凭肌肉记忆盲滑），可以直接借用其"渐进式专家化"思路。

## 对标产品：BetterAndBetter

**BetterAndBetter（下称 BAB）是一款免费的国产全能效率工具，触控板手势是它的核心卖点，但用法建立在"记忆"之上。** 它仍在维护，Homebrew 上的最新版本为 2.7.9（2026 年 6 月构建）。

**功能构成**

- **触控板动作手势**：覆盖单指到五指，一百余种，包括四角与四边轻点/点按、多指轻点、滑动、合拢张开、"某指按住另一指滑动"等组合。
- **触控板绘图手势**：画出字母或图形触发动作，两种触发方式：按住 Fn 单指画；**拇指贴住触控板底边，另一指画**。
- **鼠标**：8 键鼠标按键绘图、按键组合、滚轮反转与平滑滚动、妙控鼠标手势。
- **键盘**：全局及单应用快捷键。
- **执行动作**：三类——内置预设（几十种）、AppleScript 脚本库、模拟快捷键。
- **其他模块**：情景模式、自动跳窗（类 PopClip）、屏幕四角触发、窗口吸附分屏、蓝牙解锁、剪贴板管理、菜单栏系统监控。

**对我们的两点启示**

1. BAB 的"拇指贴底边 + 单指绘图"已经证明：**用一根静止手指做修饰键**在妙控板上可行，用户也能接受。我们的锚指是同一思路。
2. BAB 的痛点正是我们的机会：手势多到记不住；多指、轻点类手势容易和系统手势、日常点按冲突；所有手势都要"盲做"，做错了没有反馈。

| 维度 | BetterAndBetter | 本产品 |
| --- | --- | --- |
| 选择方式 | 回忆手势或图形，盲做 | 屏幕上看着选，所见即所得 |
| 记忆负担 | 每个动作一个手势，随数量线性增长 | 只记一个唤起手势，动作靠位置 |
| 冲突面 | 一百多种手势分布在全部手指数和全部区域 | 只占用一个角落；激活态之外不介入 |
| 容错 | 识别错误直接执行 | 松手前可见可改，安全区可取消 |
| 可容纳动作数 | 受手势数量限制 | 受面板槽位数限制，可按应用切换面板 |
| 功能广度 | 极广（鼠标、键盘、窗口、剪贴板等） | 初期只做触控板面板，动作库对齐 BAB |

定位建议：不与 BAB 拼功能广度，而是做"**触控板上的可视化快捷面板**"这一个点，把它做到极致；动作类型对齐 BAB 的三大类即可覆盖大多数用户需求。产品免费开源：价格上与 BAB 持平，靠开源换取社区贡献的面板模板与动作。

## 技术可行性

**七项关键能力中四项是成熟做法，三项需要原型验证：激活态下的系统事件屏蔽、后台冻结光标、触觉反馈；另需实测原始触点帧率。** 整体技术栈建议 Swift + AppKit（浮层与事件）+ SwiftUI（设置与编辑器）。

| 能力 | 实现方案 | 判断 | 关键风险 |
| --- | --- | --- | --- |
| 读取原始触点 | 私有框架 MultitouchSupport：枚举设备、注册接触帧回调；每指给出 ID、0–1 归一化坐标、速度、接触面积 | 成熟 | 私有 API，每个 macOS 大版本需回归；内置板与妙控板要分设备处理 |
| 屏蔽系统事件 | CGEventTap 在激活态内丢弃指针移动、滚动、点按、缩放/旋转事件 | **需验证** | 只能挡住普通事件；三、四指的系统手势由 Dock 私有消费，挡不住 |
| 冻结光标 | 进入激活态记录光标位置，用事件拦截丢弃指针移动并逐帧校验，退出时恢复 | **需验证** | 系统的"断开鼠标与光标关联"接口面向前台应用，对后台应用可能无效，故改走事件拦截 |
| 浮层面板 | 非激活型 NSPanel，高窗口层级，跨所有桌面和全屏应用显示，鼠标穿透 | 成熟 | 显示在"冻结光标所在的屏幕"，多屏需处理 |
| 动作执行 | 合成按键事件、NSWorkspace 打开应用/URL、Process 执行命令、AppleScript/JXA、快捷指令命令行 | 成熟 | 面板不抢焦点，按键才能发给原前台应用 |
| 触觉反馈 | 公开的 NSHapticFeedbackManager，悬停切换槽位时轻震 | 需验证 | 仅力度触控板有效；后台应用触发是否生效需实测 |
| 分发与权限 | 非沙盒，Developer ID 签名 + 公证；需辅助功能权限，脚本类动作需自动化权限 | 成熟 | 不能上 Mac App Store；每次更新版本可能需用户重新授权 |

**三个必须理解的技术事实**

1. **读触点和挡事件是两套独立机制。** 读取原始触点本身不需要任何权限，但它只是旁听：系统照样会根据这些手指生成滚动、点按和手势。所以"不干扰正常使用"很容易，"激活态内不被系统干扰"才是难点。开源工具 MiddleDrag 的做法与我们一致：私有框架读触点，CGEventTap 压制冲突的点按事件；它也坦言用力按压仍可能触发 Mission Control。
2. **激活态必须严格限制为两指。** 锚指 + 指点指在系统眼里是双指，产生的滚动、缩放都是普通事件，可以挡掉；第三根手指一落下，就可能进入系统三指手势的范围（切换桌面、查词、拖移）。因此规则是：激活态内出现第三指立即取消。
3. **帧率决定跟手感。** 一份公开测试在 M4 Max 上 60 秒约 2900 帧，未说明是否持续触摸。若实际只有约 50 Hz，面板指示点需要插值或预测才能在 120 Hz 屏上流畅；原型阶段先测量真实帧率与端到端延迟。

来源：[MiddleDrag 实现说明](https://github.com/jeecrypt/MiddleDrag)、[go-macos/multitouch 文档](https://pkg.go.dev/github.com/go-macos/multitouch)、[OpenMultitouchSupport（Swift 封装）](https://github.com/KrishKrosh/OpenMultitouchSupport)

### 深入风险评估：理论上能不能做

**能做：没有任何一环被系统规则明确禁止，不存在原理性死路。** 真正的工作量在于把下面几处边界情况一一测干净。

| 确定程度 | 风险点 | 判断依据 | 对策 |
| --- | --- | --- | --- |
| 确定可做 | 读取原始触点 | 私有框架自 OS X 10.5 起接口稳定；BAB、BetterTouchTool、MiddleDrag 均依赖它；只读不需权限 | 无需额外处理，每个大版本回归 |
| 确定可做 | 激活态之外不干扰 | 读触点是旁听，不碰任何事件 | 无 |
| 确定可做 | 浮层、快捷键、打开应用/URL、脚本 | 公开 API 常规用法 | 无 |
| 需实测 | 后台冻结光标 | "断开关联"接口按前台应用设计，SDL 源码显示焦点切换时需重新应用；Chromium 测试代码则用事件拦截实现光标脱钩 | 直接走事件拦截路线，逐帧校验光标并拉回 |
| 需实测 | 屏蔽双指产生的事件 | 滚动、双指轻点右键、智能缩放、捏合、压力事件都是普通事件，理论上可丢弃 | 激活态全部丢弃；退出后继续丢弃惯性滚动阶段的事件（开源窗口管理器 paneru 用 1200 ms） |
| 需实测 | 原始触点帧率 | 公开数据仅一条，未说明是否持续触摸 | 不影响可行性；最坏用插值补帧 |
| 设计规避 | 三、四指系统手势 | 由 Dock 私有消费，第三方普遍无法可靠拦截 | 激活态只允许两指，第三指落下即取消并放行 |
| 设计规避 | 右边缘双指左滑打开通知中心 | 同属 Dock 系手势 | 映射区避开边缘；实测是否误触发 |
| 设计规避 | 候选期光标先跑一段 | 驻留判定期间事件仍在放行 | 锚指落下即先拦指针移动并累计位移；判定失败再把光标补到应到位置（已写入 R1） |
| 设计规避 | 与 BetterTouchTool / BAB 共存 | 双方都拦截事件，先后取决于拦截顺序 | 检测到时提示，并建议关闭它们在同一角落的手势 |
| 外部不可控 | Apple 改动私有框架或收紧事件拦截 | 15 年未变，但无保证 | 每个大版本回归；开源社区可快速修补 |
| 外部不可控 | 更新后辅助功能授权失效 | 系统按签名识别应用 | 始终使用同一个 Developer ID 签名 |

**唯一可能的"一票否决"**：事件拦截在激活态下无法完全挡住双指产生的某个系统行为（例如它走 Dock 私有通道）。即便出现，也有退路：引导用户在系统设置里关闭那一个手势，或把锚定区换到不会触发它的位置。

**验证顺序**（每项一两天可出结论）：

1. 事件拦截能否在后台冻结光标，并挡住双指滚动、右键、缩放、压力事件；
2. 候选期"先拦移动、失败补位"是否无感；
3. 与 BetterTouchTool 共存时的拦截顺序。

前两项通过，产品即可基本确定能做。

## 可用性风险与对策

**误唤起是头号可用性风险，其次是"松手瞬间位置漂移"导致选错槽位。** 两者都能通过判定规则解决，但阈值必须靠真人测试定，不能拍脑袋。

| 风险 | 典型场景 | 对策 |
| --- | --- | --- |
| 误唤起 | 拇指习惯性搭在左下角，准备物理按压或拖拽 | 锚定判定叠加：驻留时长、静止、未物理按下、落下时板上无其他手指、接触面积不超过手掌阈值 |
| 与系统设置冲突 | 用户开启了"点按左下角"作为辅助点按 | 首次启动检测该设置，提示改用其他角或关闭该项 |
| 唤起的同时想点按 | 锚指落下后用户其实要按下去点击 | 物理按下即放弃锚定，原样放行点按 |
| 松手漂移 | 手指抬起时最后几帧坐标抖动，落到相邻槽位 | 提交位置取抬起前约 50–80 ms 的稳定点；槽位切换加滞回（进入要越过边界一小段距离） |
| 槽位过小 | 手指接触面积约 1 cm，13 寸内置板上格子太密点不准 | 编辑器按触控板物理尺寸校验最小槽位；不同尺寸设备各自换算 |
| 锚指挡路 | 锚指占着左下角，指点指去不了映射区左下部 | 映射区避开锚定区所在角；默认布局在该角放安全区 |
| 锚指滑动 | 用户按住时拇指无意滑动出锚定区 | 激活后锚指只看"是否仍在板上"，不再要求停留在锚定区 |
| 第三指落下 | 用户换手或手掌碰到 | 立即取消，并放行后续系统手势 |
| 发现性 | 新用户不知道有这个手势 | 引导教程 + 首次锚定时面板带提示文字 |
| 特殊应用 | 游戏、远程桌面、虚拟机自己处理触控板 | 按应用黑名单整体停用 |

**借用 Marking Menu 的渐进式专家化。** 熟练用户会在面板出现前就开始滑向目标。建议：锚定成立后面板延迟约 150–300 ms 再显示（可配置）；在这之前指点指已经落在某槽位并抬起，也照常执行。新手看面板选，老手凭位置盲选，同一个面板两种用法。

**按应用切换面板是降低记忆负担的放大器。** 同一个位置，在浏览器里是"关闭标签"，在编辑器里是"关闭文件"，用户记的是"右上角是关闭"这一个语义，而不是两个手势。

## 细化后的需求

**整个交互是一个五状态的状态机：空闲 → 候选 → 激活 → 提交或取消 → 冷却。** 状态机外的一切触控板输入原样放行，这是"不介入不干扰"的保证。

&#91;embedded content: 激活态状态机 · 5 个状态\]

候选期内任何不符合条件的输入都会立即放弃并原样交还系统；只有激活态才屏蔽事件，且所有退出路径都经过冷却。

### 交互规则

1. **R1 锚定判定**（候选 → 激活），以下全部满足：
   1. 一指落点在锚定区内，且落下时板上没有其他接触；
   2. 静止驻留不少于驻留时长，期间位移小于静止阈值；
   3. 期间未发生物理按下（按下即放弃，放行点按）；
   4. 接触面积低于手掌阈值。候选期内先只拦截指针移动并累计位移：判定成立则光标纹丝不动；判定失败则把光标补到应到的位置后恢复放行。
2. **R2 进入激活态**：记录并冻结光标；开启事件屏蔽（指针移动、滚动、点按、缩放、旋转）；按前台应用选面板，无专属面板时用全局面板；面板在显示延迟后出现，位置在光标所在屏幕。
3. **R3 指点指识别**：激活后第一根落在映射区的新接触即为指点指。映射区 = 触控板去掉四周边距后的矩形，线性绝对映射到面板矩形，越界坐标钳制在边缘。各设备独立判定和映射，锚指与指点指必须在同一设备上，设备可单独停用。
4. **R4 悬停**：指示点实时跟随；所在槽位高亮；槽位切换带滞回和可选轻震；指点指中途抬起又落下，按新位置继续选择。
5. **R5 提交**：默认抬起提交，可选按压提交。提交位置取抬起前的稳定点。落在安全区或槽位间空隙 = 不执行。开启"连续触发"的槽位：提交后执行动作但不退出激活态，锚指不抬时指点指可再次落下重复触发（适合音量、翻页）。
6. **R6 取消**：锚指先于提交抬起；出现第三根手指；按 Esc；在安全区提交。
7. **R7 退出**：隐藏面板 → 停止拦截指针移动并校正光标位置 → 关闭事件屏蔽 → 执行动作（若有）→ 进入冷却期，期间不接受新的锚定，并继续丢弃迟到的点按与惯性滚动事件。

### 面板与编辑器

- 布局两种模式：网格（行列数可调，可合并单元格）与自由矩形；面板固定为所用触控板的物理宽高比，不可拉伸；编辑区按此比例显示。
- 槽位属性：名称、图标（SF Symbols / 应用图标 / 图片）、颜色、动作、可选的生效应用范围。
- 面板作用域：全局面板 + 按应用面板；应用面板可"继承全局并覆盖部分槽位"。
- 预置模板：浏览器、代码编辑器、媒体控制、窗口管理各一套，首次启动可直接用。
- 校验：槽位小于最小物理尺寸、与锚定区重叠时给出警告。
- 配置以 JSON 导入导出，便于分享和备份。
- 子面板（某槽位悬停驻留后进入下一层）放到 v2，避免早期把"记位置"又变回"记层级"。

### 已定决策

- **连续触发**：允许。作为槽位级开关，默认关；开启后提交不结束激活态（见 R5）。
- **面板比例**：固定为所用触控板的物理宽高比，不可拉伸，保证绝对映射不变形。
- **多设备**：内置板与外接妙控板各自独立判定、独立映射；锚指与指点指须在同一设备上；每台设备可单独停用。
- **商业模式**：免费开源。建议采用 MIT 或 GPL-3.0 许可，GitHub Releases + Homebrew Cask 分发，Sparkle 做自动更新。
- **映射区边距**：按"每边留边"理解；5% 只是暂定值，原型阶段实测后调整。
